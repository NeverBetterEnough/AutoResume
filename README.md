# Resume Pilot · 简历投递助手

面向 Chrome / Edge 的 Manifest V3 浏览器插件。上传简历、维护个人知识库、配置自己的模型，随后在当前职位申请页面启动 Agent。它会读取页面结构，按职位定制填写计划，执行填写，并重新观察动态字段。

## 安装与使用

环境：Node.js 20+、npm，Chrome / Edge 116+。

```powershell
npm install
npm run build
```

1. 打开 `chrome://extensions` 或 `edge://extensions`，开启「开发者模式」。
2. 点击「加载已解压的扩展程序」，选择本项目的 **`dist` 目录**。
3. 打开插件侧边栏，在「我的资料」上传 PDF、DOCX、TXT 或 MD 简历，检查提取文本；可维护多个版本并选择当前简历。
4. 在「知识库」保存兴趣、优势、自我评价、工作期待等真实回答。条目支持分类、关键词、搜索、编辑、删除、JSON 导入导出。
5. 在「模型设置」配置 DeepSeek 或智谱的 API Key、模型和 Base URL，点击测试连接，再保存设置。使用自己的平台账户结算模型费用。
6. 在招聘网站打开职位申请表，点击工具栏里的插件图标打开侧边栏。确认顶部「目标页面」是申请表，点击「连接当前页面」或直接启动 Agent；如果浏览器弹出站点授权，允许当前站点后继续。连接检查不会调用模型。
7. 查看执行记录、待补充项与填写方案。检查页面内容后，由你手动进入下一步或提交；每个新步骤重新启动 Agent。

默认开启自动填写；关闭「生成计划后自动填写」可先编辑方案、取消勾选，再执行选中项。自动填写最多进行 3 轮，可在设置中调整为 1–5 轮。停止任务不会清空已写入的字段。

## 已实现

- **本地资料管理**：基本资料、多个简历版本、文本检查与修改；附件保留原始文件，修改提取文本不会修改附件。
- **本地简历解析**：PDF.js 提取 PDF 文本，Mammoth 提取 DOCX 文本；TXT / MD 使用 UTF-8。最大 8 MB、30 页 PDF、10 万字符。扫描版 PDF 需先 OCR。
- **知识检索**：中文单字与双字词、英文关键词加权匹配，标题及关键词权重更高，选择相关条目进入模型上下文。
- **模型适配**：DeepSeek、智谱分别保存配置；支持兼容的 HTTPS 网关和 localhost HTTP 调试端点；SSE 流式接收、JSON 格式计划、Zod 结构校验、90 秒超时、可取消请求与错误提示。
- **Agent 循环**：观察 → 检索资料 → 生成计划 → 校验字段及来源 → 执行 → 读取验证 → 按需重新规划。验证不通过及资料不足的必填项会明确显示。
- **页面执行**：文本、邮箱、电话、日期等原生 input、textarea、select、单选、复选、contenteditable、暴露 ARIA 选项的 combobox、简历附件上传；触发原生 input / change 事件以兼容常见受控表单。
- **动态表单**：每轮重新发现新增字段；支持 open Shadow DOM、同源 iframe。字段使用内容脚本内的对象映射，不执行模型提供的选择器或 JavaScript。
- **审核与沉淀**：可编辑填写计划、手动执行选中项；模型建议的常见回答须点击「确认入库」后保存。
- **记录**：会话内执行详情、最近 50 次填写摘要；不静默恢复因后台重启中断的任务。

## 事实与执行边界

资料优先级为个人资料 → 已确认知识库 → 简历 → 基于已有事实组织表达。模型指令禁止捏造学校、学历、公司、日期、薪资等客观信息；代码层另外限制生成内容仅能写入 textarea / contenteditable，并可完全关闭生成。模型仍可能出现事实或字段匹配错误，请检查方案和页面结果。

插件保留已有字段内容，跳过密码、验证码、银行卡、身份证、隐私同意和条款字段，不提供自动点击、翻页或提交工具。附件仅使用选中的本地简历。计划绑定原标签页、文档 ID 与页面 URL；页面导航或字段语义改变时会阻止旧计划写入。

## 数据与权限

- 不依赖自建后端。简历、知识库和配置存入 `chrome.storage.local`；执行过程存入 `chrome.storage.session`。
- API Key **未加密**，仅限扩展可信上下文访问，不进入模型提示词、页面消息、错误正文或知识库导出。卸载插件会清除本地数据，请自行导出需保留的知识条目。
- 启动时向所选模型端点发送基本资料、当前简历文本、相关知识、页面文字与字段、先前执行反馈。上传简历到插件时只进行本地解析；附件上传到招聘网站发生在执行页面填写时。
- `tabs` 用来读取并确认当前标签页的地址和标题，不授予网页正文访问权。`activeTab` / `scripting` 读取用户当前授权的页面；`sidePanel` 提供侧边栏；`storage` / `unlimitedStorage` 保存原始附件及资料。默认只授权两个模型官方 API 域名，招聘站点和自定义 API 域名按需申请；启动只请求当前站点，不请求所有站点的实际访问权。
- 知识库导出包含基本资料及知识条目，不含密钥或简历附件；导入仅合并知识条目，按相同标题与正文去重。

`tests/fixtures/application.html` 是本地模拟职位申请表。端到端测试实际加载编译后的 MV3 插件，用模拟模型服务检查跨进程消息、原生字段写入、知识来源、附件上传、条件字段重新规划、不覆盖及不提交行为。测试不使用真实 API Key，不产生真实投递。`artifacts/` 保存测试截图。

```text

  content.ts          页面消息入口
```

## 初版适用范围

当前是**单个申请页面的表单填写 Agent**。跨域 iframe 请在独立标签页中打开后运行；closed Shadow DOM、Canvas 表单、未暴露可访问选项的复杂组件、多选下拉、富文本附件编辑器需要站点适配。验证码、登录、翻页、重复经历的「新增一条」按钮、最终提交由用户处理。暂不支持扫描件 OCR、旧版 DOC、跨站批量搜岗投递、附件云同步。

下一步可通过站点适配器扩展常见 ATS 的动态下拉与经历列表，再加入多步骤状态跟踪、投递去重与人工确认后的提交。

模型接口依据：[DeepSeek 官方文档](https://api-docs.deepseek.com/)、[智谱官方快速开始](https://docs.bigmodel.cn/cn/api/introduction)、[智谱对话补全](https://docs.bigmodel.cn/api-reference/模型-api/对话补全)。默认模型参考 2026-10-23 文档：`deepseek-flash`、`glm-5.3`；可按账户权限自行修改。扩展侧边栏使用 [Chrome Side Panel API](https://developer.chrome.com/docs/extensions/reference/api/sidePanel)。

## 模型连接故障排查

GLM-5.3 强制开启思考，不接受 `thinking.type: "disabled"`。插件为它发送 `thinking.type: "enabled"` 与 `reasoning_effort: "low"`，测试连接与 Agent 使用相同的模型参数适配。参考 [GLM-5.3 官方迁移说明](https://docs.bigmodel.cn/cn/guide/models/text/glm-5.3)。

请求失败时会展示 HTTP 状态、服务端结构化错误码和经过密钥脱敏的错误信息。HTTP 400 不等于 API Key 无效；应优先根据具体错误检查模型参数与接口地址。标准智谱 Chat Completions 的 Base URL 为 `https://open.bigmodel.cn/api/paas/v4`。如果使用其他产品类型的 Key，请核对该产品允许的端点与模型。

更新代码后需重新执行 `npm run build`，在扩展管理页点击「重新加载」，并关闭后重新打开插件侧边栏，确保使用的是新版本后台与界面。

### 无法读取当前页面

浏览器会在没有当前页面授权时省略标签页的 URL。0.1.0 曾把「URL 不可见」误报为「不是 HTTP / HTTPS 页面」；0.1.1 已区分「内部页面」「缺少授权」「标签页已关闭」。每次启动会重新获取当前标签页，避免侧边栏打开后切换网页仍使用旧页面。

0.1.2 改为在「连接当前页面」或「启动 Agent」的点击事件中直接申请当前站点访问权，用户不再需要反复依赖临时 `activeTab` 授权。授权完成后会再次核对标签页和站点，若授权期间切换了页面则中止，不会写入其他网页。扩展管理页、设置页和本地文件仍不可填写。

### 0.1.2 启动修复与详细诊断

- 工具栏点击显式绑定当时的标签页并打开侧边栏。顶部展示实际目标页面，可先连接以验证页面读取，不消耗模型额度。
- 注入失败保留浏览器原始错误、错误码、堆栈、内层 cause。只有明确的访问拒绝才提示站点授权；`TypeError`、`ReferenceError`、上下文失效和消息超时分别报错。
- 页面脚本以扩展 ID、版本、消息监听器存活状态建立握手。重载后不再因旧版的布尔「已安装」标记跳过初始化；旧 runtime 的 ID 在安装时捕获，避免消息处理时访问失效的 `chrome.runtime.id`。
- 捕获侧边栏和后台的全局错误及未处理 Promise，记录解析标签页、授权结果、注入、握手、观察页面和模型规划阶段。日志分上下文保存，最多保留 160 条，不包含简历正文和模型答案，密钥及 URL 查询参数脱敏；仅本地保存，不自动上传。
- 点击「查看诊断日志」查看最近失败阶段，使用「复制诊断日志」或「导出诊断日志」取得 JSON。日志包含插件版本、浏览器版本、扩展 ID、标签页 ID、站点地址及完整错误栈。构建保留 source map 以便定位源码。

更新到 0.1.2 后，请在扩展管理页确认新版本已启用。新增的 `tabs` 权限仅用于目标页元数据；网页内容访问权由当前站点的授权弹窗单独控制。关闭旧侧边栏并刷新招聘页面，然后重新打开插件，可清除之前失效的页面上下文。

回归测试覆盖真实扩展的页面连接与填写、未经额外授权时的真实访问拒绝，以及与截图同形的注入 `undefined.id` 异常的分类和日志导出。成功填写用例在测试配置中预先授予本地测试站点权限，并以扩展标签页模拟侧边栏的目标页查询；模型服务使用模拟响应。原生站点授权弹窗由用户确认，不在测试中绕过真实用户选择。
